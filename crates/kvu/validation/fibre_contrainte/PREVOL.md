## 2. Commandes exactes (acemagic) et contrôle d'inventaire
Un seul script haché, `validation/fibre_contrainte/lancer_verdicts.sh` : construit le binaire de test, exécute dans l'ordre FIB-STAT-CALIB (son échec arrête le lot), `gates_commun`
(ENTREE-WP11), `gates_jacobien`, `gates_penalite`, `gates_rattle`, `gates_su2` (chaque commande `<binaire de test> fibre_contrainte::<module> --include-ignored --nocapture
--test-threads=1`, `--skip fib_stat_calib` pour `gates_penalite`, `--skip explo` pour `gates_su2`, sous `calc_borne --mem 20G`, environnement `env -i PATH HOME TMPDIR CARGO_TARGET_DIR
FIBC_FILS=16`), puis `cargo test --release --test fibre_contrainte_cli`, enregistre le code retour de chaque commande (`rcs.txt`), extrait les lignes `PASS|FAIL|SKIP` (préfixe
« test <nom> ... » retiré) dans `verdicts.txt` et lance `inventaire.py verdicts.txt rcs.txt cli.log` (rc 0 ⇔ tous les IDs attendus, tous PASS, aucun FAIL ni SKIP de gate, tous les codes
retour nuls, 4 tests CLI verts). Le binaire du lot (`build_auto.sh`, KVU_LOT=wp12a) est construit à part : `U/bin/wp12a/acemagic/kvu` (+ `.sha256`, `.commit`).
